## 三、本插件的定位差异（对比后确认独有）

逐个读完 13 个直接同行后，**没有第二个**做下面任何一件事：

1. **把「局势模型」当核心对象**。其余全部是"改写草稿"或"给建议"，产物形态是"一段更好的提示词"或
   "一个选中的方法模板"；只有本插件产出 `intent / situation / tensions / directions /
   recommendation / questions / tree` 这套可审查、可比较的**结构化决策结构**。
2. **增量更新（续研）**。`resume=true` 把本会话上一份局势模型带回去，让模型"更新原树"而不是
   "重新生成一段漂亮长文"，并显式标记 `rejected` / `superseded` 节点。
3. **把缩进树定义为视图而非产物**。树节点带 `type/source/confidence/impact/status` 五属性，
   且强制区分**事实 / 推断 / 假设 / 未知**（同行里只有 `Zleitai` 有保真校验，但没有这层分类）。
4. **「暂不推荐」是合法输出**。信息不足时不硬拍板，而是给待确认问题；同行全部默认"一定要给出改写结果"。
5. **失败即给换模型入口**。这是上一轮修出来的：区分"只出思维链"与"完全空白"，自动弹出模型选择框。

一句话：**同行都在做"把这句话改写得更专业"，本插件在做"把这个问题想清楚"。**

## 四、生态里已成标配、本插件确实缺的（按性价排序）

### 1. 提示词外置 + 编号硬约束（最高性价比）
`Zleitai/dsh-prompt-enhancer` 的 `lib/meta-prompt.js` 是本次对比里最值得抄的一份资产：

```
C1 语言锁定    输出语言必须与输入完全一致，不因术语是英文而整体切换
C2 术语豁免    技术术语/路径/URL/变量名保持原样，不翻译不音译
C3 意图锁定    只能增加结构，不能替换或泛化锚点（"这个月"≠"近30天"）
C4 否定与范围强制保留   每个否定词/范围限定词必须原义出现，遗漏即失败
C5 缺失不虚构  不得编造数据源名称/数值/文件名，一律用 [占位符]
C6 体例锁定    不得擅自升格为公文腔或营销腔
C7 长度控制    不超过原输入 12 倍且不超 400 字
C8 能力边界    只允许引用 context 中列出的能力，超出则追加 [能力缺口: …]
```

它还记录了一个反直觉但重要的经验：**元提示用什么语言写，输出就偏向什么语言**。
我们的 `ADVISOR_SYSTEM_PROMPT`（3548 字符）是散段落，**没有编号**，因此：
- 测试里没法逐条断言"C4 否定词是否保留"
- 出了问题没法定位是哪条约束失效

### 2. 读工作区上下文（多数同行有，我们 0）
`ai-polish`、`dsh-prompt-polish`、`dsh-better-input` 都会读会话工作区的项目上下文再增强。
本插件只用输入框那一句 —— 这直接限制了参谋分析质量（它无法知道你在哪个仓库、改什么项目）。

### 3. settings 注册（同行 7/27，我们 0）
同行把行为做成设置页可调项；我们把 `ADVISOR_MAX_TOKENS`、`ADVISOR_TIMEOUT_MS`、
`isFastModel` 的模型黑名单正则**硬编在代码里**。上一轮"输出预算该由谁定"的争议，
根因就是没有 settings 出口。

### 4. 前后对比预览 + 采纳后撤销（同行普遍有，我们 0）
我们直接 `setDraft` 整段替换草稿，用户看不到改了哪里，也没有一键还原。

### 5. 模型回退链（我们只有"失败弹框"）
`ai-polish` 做到"网关不支持某参数时自动去参重试"；我们止步于让用户手选。

### 6. 工程配套
- **类型定义 `.d.ts`**：11/27 有（`dsh-context`、`dsh-better-display` 等），我们 0。
- **测试**：14/27 有测试文件；我们有 3 套离线测试（host-parse/advisor/smoke），**这项我们领先**。
- **双语 README**：18/27 有（含 `README.zh.md` / `README.i18n.yaml`），我们只有中文。
- **提示词资产校验脚本**：`LeiQAQ` 的 `verify-prompts.mjs` 值得借鉴到我们的 `test/advisor.mjs`。

## 五、"参谋/决策"这个方向的邻居

- **`leeyoung1/dsh-advisor-plugin`（7500 行）** —— 名字最接近"顾问"，但**架构完全不同**：
  它不产出局势模型，而是把**快执行模型 + 强审查模型**配对，审查模型按
  `plan / correction / stop` 三选一契约回文，**作为工具结果交还执行模型，不进人类可见对话流**。
  设计取向是"执行与判断分离、建议权≠执行权、按需升级、未武装时零提示词成本"。
- **`afoxsss/dsh-conversation-map`** —— "会话地图"，是对话层级可视化，不是决策结构。

→ 结论：**"带局势模型的战略参谋"这个位置目前是空的**，本插件是唯一占位者。

## 六、方法论说明与本次分析的已知误差

自动扫描用正则判"有无某能力"，**误报率不低**，已逐项人工核验并剔除：
- "工作区上下文"：正则命中 `dsh-workspace`（那只是路径字符串），**实为无**。
- "模型回退链"：命中 `fallbackText`（那是降级文本字段），**实为无**。
- "限流保护"：认为无；实际 `install.ps1` 里没有任何限流逻辑。
- 同行侧的"提示词存在"用文件名判据（26/27），宽松；"settings 注册"用 `ctx.settings.register(` 严格判据（7/27），可信。

因此本报告第四节的行内数字以**严格判据**为准，第三节的"独有"结论以**逐文件阅读**为准。

## 七、可执行的下一步建议（若继续 v0.3）

1. 把 `ADVISOR_SYSTEM_PROMPT` 重构成编号约束（C1…Cn），每条附反例，并在 `test/advisor.mjs` 里逐条断言。
2. 接入会话工作区上下文（`ctx.workspace` 或会话 API）作为 `【已知背景】` 的自动来源。
3. 注册 settings：模型偏好、输出预算、超时、易空正文模型黑名单。
4. 采纳前 diff 预览 + 一键撤销（`setDraft` 前保存原草稿）。
5. 失败时先自动回退到 `isFastModel` 白名单里的下一个模型，全部失败再弹选择框。
